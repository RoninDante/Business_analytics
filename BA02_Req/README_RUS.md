# Проект 02. Роль и функции ИТ-аналитика в команде разработки ИТ-систем

## Введение

Типовой жизненный цикл разработки программного обеспечения состоит из этапов: обследование, проектирование, разработка, тестирование, внедрение, эксплуатация, вывод из эксплуатации. Рассматривается типовой состав команды и работы на каждом этапе, а также несколько навыков ИТ-аналитика:

1. Выявление источников информации.
2. Единство терминов и понятий (ведение глоссария).
3. Декомпозиция.

## Теоретические сведения

### 1. Жизненный цикл разработки ИТ-систем

Любое ПО проходит через 6 основных этапов:
- Обследование (сбор требований);
- Проектирование;
- Разработка;
- Тестирование;
- Внедрение;
- Сопровождение.

В команде разработки присутствуют специалисты, выполняющие такие роли: ИТ-аналитик, архитектор, разработчик, тестировщик, специалист внедрения/сопровождения, менеджер, специалист DevOps, технический писатель.

### 2. Выявление источников информации

Создается каталог источников информации с параметрами:
- Источник (название, автор, дата выпуска);
- Адрес размещения;
- Приоритет изучения;
- Актуальность, легитимность;
- Дата ввода/прекращения действия;
- Кто добавляет;
- Дата занесения;
- Отметка об изучении;
- Примечание.

### 3. Глоссарий

Для исключения путаницы в понятиях создается глоссарий, который поддерживается на протяжении всей работы.

### 4. Правила размещения, именования

Рекомендуемые правила:
- Для каждого продукта (задачи) определить префикс и создать отдельную директорию.
- Текстовые рабочие документы сохранять в формате .xlsx.
- Каталоги кодировать (например, STA — каталог стейкхолдеров, INF — каталог источников информации).

### 5. Декомпозиция. Основные понятия

Декомпозиция — процесс разделения целого на части.

Виды декомпозиции:
- Функциональная (структурирование функций)
- Объектная, компонентная (расчленение на объекты)
- Структурная (структурирование по выбранным критериям)
- Темпоральная, событийная (разделение по времени, по событиям)

### 6. Правила декомпозиции

1. **Подчиненность** — построение сверху вниз.
2. **Единственность критерия** — система расчленяется только по одному критерию для уровня.
3. **Целостность**:
   - Полнота: подсистемы в сумме полностью характеризуют систему верхнего уровня.
   - Взаимное непересечение: элементы одной группы не входят в другую группу.

### 7. Рекомендации по построению декомпозиции

Перед выполнением декомпозиции определить:
1. Зачем декомпозировать?
2. Для какого пользователя?
3. Какой показатель выбираем для разбиения?
4. По каким критериям разделять?
