## Упражнение 02 — Раздел `<schema>`

*Требования чек-листа: определены функции 5 элементов/атрибутов, даны ответы на 4 вопроса, каждый пункт — одним предложением, результаты в таблице.*

### Часть 1: Функции элементов и атрибутов

| № | Элемент / Атрибут | Функция (одним предложением) |
|---|---|---|
| 1 | `<element>` | Описывает отдельное поле (узел) XML-документа: его имя, тип данных и правила вхождения в сообщение |
| 2 | Атрибут `type` элемента `<element>` | Задаёт тип данных элемента — например, `xs:string`, `xs:integer`, `xs:decimal` — и определяет, какие значения допустимы |
| 3 | `<complexType>` | Описывает составной (сложный) тип данных, содержащий несколько вложенных дочерних элементов |
| 4 | `minOccurs` | Задаёт минимальное количество раз, которое данный элемент может встречаться в XML-сообщении |
| 5 | `maxOccurs` | Задаёт максимальное количество раз, которое данный элемент может встречаться в XML-сообщении |

### Часть 2: Ответы на дополнительные вопросы

| № | Вопрос | Ответ (одним предложением) |
|---|---|---|
| 1 | Что означает элемент `<sequence>`? | Элемент `<sequence>` указывает, что вложенные дочерние элементы должны следовать в XML-сообщении строго в том порядке, в котором они описаны в схеме |
| 2 | Что означает отсутствие `minOccurs` или `maxOccurs`? | Если атрибуты не указаны явно, оба принимают значение по умолчанию `1` — элемент обязателен и встречается ровно один раз |
| 3 | Что означает `maxOccurs="unbounded"`? | Элемент может встречаться в XML-сообщении неограниченное количество раз, то есть представляет собой массив (список) значений |
| 4 | Как понять, обязателен ли элемент? | Элемент обязателен, если `minOccurs="1"` или значение не указано (по умолчанию `1`); если `minOccurs="0"` — элемент является необязательным |

## Упражнение 04 — Обратное проектирование, дополнение

*Требования чек-листа: указана разница между выходными сообщениями getAllMembers и getMemberByName; результат сформулирован одной фразой.*

### Сравнение выходных сообщений

| Параметр сравнения | `getAllMembers` | `getMemberByName` |
|---|---|---|
| Тип выходного элемента | Массив объектов Member (`maxOccurs="unbounded"`) | Один объект Member (`maxOccurs="1"`) |
| Количество записей | Все члены клуба (0 и более) | Не более одного члена клуба |
| Атрибут `maxOccurs` | `unbounded` | `1` (или не указан — по умолчанию `1`) |
| Может быть пустым | Да (пустой массив) | Да (пустой элемент, если не найден) |

**Ответ одной фразой:**

> Операция `getAllMembers` возвращает массив (коллекцию) объектов всех членов клуба с атрибутом `maxOccurs="unbounded"`, тогда как `getMemberByName` возвращает единственный объект одного конкретного члена клуба с атрибутом `maxOccurs="1"`.

## Упражнение 05 — Определение конечной точки

*Требования чек-листа: определены endpoint-URL для обоих сервисов, представлено в таблице.*

| № | Веб-сервис | WSDL-файл | Конечная точка (endpoint URL) |
|---|---|---|---|
| 1 | Сервис членов клуба (Members Service) | member.wsdl | `http://localhost:8080/ws/member` |
| 2 | Сервис питомцев (Pets Service) | pet.wsdl | `http://localhost:8080/ws/pet` |

<details>
<summary>📄 Как определяется конечная точка в WSDL (нажмите, чтобы развернуть)</summary>

Endpoint указывается в теге `<service>` → `<port>` → `<soap:address location="...">`:

```xml
<!-- member.wsdl -->
<service name="MemberService">
  <port name="MemberPort" binding="tns:MemberBinding">
    <soap:address location="http://localhost:8080/ws/member"/>
  </port>
</service>

<!-- pet.wsdl -->
<service name="PetService">
  <port name="PetPort" binding="tns:PetBinding">
    <soap:address location="http://localhost:8080/ws/pet"/>
  </port>
</service>
```

</details>
