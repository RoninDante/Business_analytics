## Упражнение 02 — Обновление UC04

*Полная последовательность шагов UC04 «Регистрация клиента менеджером» с указанием компонента приложения, роли и метода интеграции.*

**Контекст использования:** Менеджер, общаясь с клиентом по телефону, регистрирует клиента для заказа услуги.  
**Главный актор:** Менеджер.  
**Предусловие:** Клиент позвонил менеджеру. Менеджер авторизован в веб-приложении парикмахерской.

### Основной сценарий

| Шаг | Описание действия | Компонент | Роль | Метод интеграции |
|---|---|---|---|---|
| 1 | Менеджер открывает страницу регистрации клиента | Клиент (браузер) | Менеджер | — |
| 2 | Менеджер вводит номер телефона и имя клиента (полученные по телефону) | Клиент (браузер) | Менеджер | — |
| 3 | Система отправляет запрос на проверку уникальности логина (телефона) | Клиент → Сервер | Система | REST GET /persons?login={phone} |
| 4 | Сервер проверяет, есть ли персона с таким логином в БД | Сервер | Система | — |
| 5 | Сервер возвращает результат: телефон не зарегистрирован (200 OK, пустой массив) | Сервер → Клиент | Система | REST-ответ |
| 6 | Система генерирует временный пароль (хранит в памяти, не в БД) | Сервер | Система | — |
| 7 | Система регистрирует клиента: создаёт запись в `Персоны` и `Клиенты` | Клиент → Сервер | Система | REST POST /clients |
| 8 | Сервер возвращает данные созданного клиента (201 Created) | Сервер → Клиент | Система | REST-ответ |
| 9 | Система отправляет SMS-уведомление клиенту (имя, логин, временный пароль) | Сервер → SMS-шлюз | Система | REST POST /sms/send |
| 10 | SMS-шлюз подтверждает отправку (200 OK) | SMS-шлюз → Сервер | Система | REST-ответ |
| 11 | На экране менеджера отображается подтверждение успешной регистрации | Клиент (браузер) | Менеджер | — |

### Альтернативный сценарий

| Шаг | Условие | Описание | Компонент | Роль | Метод интеграции |
|---|---|---|---|---|---|
| 3а | Логин (телефон) уже зарегистрирован | Сервер возвращает 200 OK с найденной персоной | Сервер → Клиент | Система | REST-ответ |
| 4а | Логин уже зарегистрирован | Система отображает сообщение: «Номер уже зарегистрирован» | Клиент (браузер) | Система | — |
| 5а | Логин уже зарегистрирован | Менеджер вводит другой номер (возврат к шагу 2) или прерывает регистрацию | Клиент (браузер) | Менеджер | — |
| 9б | SMS-шлюз недоступен | Сервер получает ошибку от SMS-шлюза (4xx/5xx); клиент зарегистрирован, но уведомление не отправлено | Сервер | Система | REST-ответ с ошибкой |
| 10б | SMS-шлюз недоступен | Система логирует ошибку и информирует менеджера об отсутствии SMS | Клиент (браузер) | Менеджер | — |

**Источники (справочники), использованные в UC:**
- Данные клиента вводятся вручную менеджером (справочников нет — только проверка уникальности логина и создание записей в `Персоны` и `Клиенты`).

## Упражнение 03 — Интеграция ссылок

*Справочники (источники), используемые в транзакции UC04 «Регистрация клиента менеджером».*

| Справочник | Используется в UC | Требуется ли интеграция | Вариант интеграции | Метод интеграции |
|---|---|---|---|---|
| Персоны (Persons) | Проверка уникальности логина (телефона) | Да | Поиск записи-ссылки по переданным данным (iv) | GET /persons?login={login} |
| Клиенты (Clients) | Создание записи клиента | Да | Передача записей, относящихся к передаваемым данным (iii) | POST /clients |
| SMS-шлюз (внешний сервис) | Отправка SMS с временным паролем | Да | Передача записей, относящихся к передаваемым данным (iii) | POST /sms/send |

**Пояснения к выбору варианта:**
- **Персоны / проверка логина:** При регистрации нужно лишь проверить наличие существующей записи по логину — вариант «iv» (найти запись-ссылку по переданным данным).
- **Клиенты:** Создаётся новая запись, связанная с персоной — вариант «iii».
- **SMS-шлюз:** Передаётся только конкретное сообщение для конкретного получателя — вариант «iii».

## *Упражнение 08 — Обновление UC02 (бонусное)

*Анализ и доработка UC02 «Создание основного расписания».*

**Контекст использования:** Менеджер создаёт расписание (слоты) рабочих дней мастера.  
**Главный актор:** Менеджер.  
**Предусловие:** Менеджер авторизован в системе. В системе есть записи сотрудников с ролью «мастер».

### Основной сценарий

| Шаг | Описание действия | Компонент | Роль | Метод интеграции |
|---|---|---|---|---|
| 1 | Менеджер открывает раздел управления расписанием | Клиент (браузер) | Менеджер | — |
| 2 | Система загружает список мастеров (сотрудники с role='мастер') | Клиент → Сервер | Система | REST GET /employees?role=мастер |
| 3 | Сервер возвращает список мастеров (200 OK) | Сервер → Клиент | Система | REST-ответ |
| 4 | Менеджер выбирает мастера | Клиент (браузер) | Менеджер | — |
| 5 | Система загружает список услуг мастера (из справочника «Услуги мастера») | Клиент → Сервер | Система | REST GET /employees/{employeeId}/services |
| 6 | Сервер возвращает список услуг мастера (200 OK) | Сервер → Клиент | Система | REST-ответ |
| 7 | Менеджер задаёт рабочие дни (даты) и временные слоты (start_time) | Клиент (браузер) | Менеджер | — |
| 8 | Система сохраняет слоты расписания | Клиент → Сервер | Система | REST POST /slots |
| 9 | Сервер возвращает подтверждение создания слотов (201 Created) | Сервер → Клиент | Система | REST-ответ |
| 10 | Менеджер видит подтверждение успешного создания расписания | Клиент (браузер) | Менеджер | — |

### Альтернативные сценарии

| Шаг | Условие | Описание | Компонент | Роль |
|---|---|---|---|---|
| 2а | Список мастеров пуст | Система отображает сообщение: «Мастера не найдены. Добавьте мастеров в систему» | Клиент (браузер) | Система |
| 8а | Пересечение слотов (слот уже занят) | Сервер возвращает 409 Conflict — временной слот уже существует | Сервер → Клиент | Система |
| 8б | Обязательное поле не заполнено | Сервер возвращает 400 Bad Request | Сервер → Клиент | Система |

**Источники (справочники) в UC02:**
- Сотрудники (с ролью «мастер»)
- Услуги мастера (связь мастера с услугами)
