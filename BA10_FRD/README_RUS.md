## Теоретические сведения

### 1. Пользовательские истории (User Story)

**Пользовательская история** — метод, позволяющий быстро понять и кратко зафиксировать потребности пользователей в системе. Краткое описание функциональности и/или качества, необходимых конкретной заинтересованной стороне для получения ожидаемой пользы.

US должен быть:
- кратким,
- простым,
- ценным,
- атомарным,
- бизнесовым.

**Описание US:**
- Заголовок (активное глагольное выражение цели)
- Тело: **Как** [роль пользователя] **я хочу/могу** [сделать то-то] **, чтобы** [получить выгоду]
- Критерии приемки (Given-When-Then)
- Тестовые сценарии

**Критерии INVEST:**
- Independent (независимость)
- Negotiable (обсуждаемость)
- Valuable (ценность)
- Estimable (оценка трудозатрат)
- Small (компактность)
- Testable (тестируемость)

## Задания

### Exercise 00 — Описание пользовательских историй (Description of user stories)

**Для роли менеджера задачи 1** постройте не менее двух US:
1. Определите потребности менеджера.
2. Для каждой потребности напишите US (идентификатор, заголовок, тело).
3. Для одного US разработайте критерии приемки.
4. Для второго US разработайте тестовый сценарий.

Распишите ответы в файле `ex00_<префикс продукта>_us_<роль>.docx`.

### Exercise 02 — Согласование пользовательских историй (Coordination User Stories)

Обсудите и согласуйте разработанные US:
1. Найдите сокурсников или друзей для обсуждения (роли «пользователь», «заказчик», «разработчик»).
2. Проверьте выполнение условий 3 С (Card, Conversation, Confirmation).
3. Проверьте характеристики INVEST.
4. Напишите протокол обсуждения.
5. Распишите ответы в файле `ex02_<префикс продукта>_us.docx`.
