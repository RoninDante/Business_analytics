## Exercise 00 — Выделение объектов, имеющих статусную модель

### Критерии выявления

Сущность требует описания жизненного цикла, если:
- её состояние изменяется в ходе работы системы;
- поведение системы зависит от текущего состояния записи;
- важно контролировать этапы для обеспечения корректности бизнес-процесса.

### Таблица сущностей со статусной моделью

| Сущность              | Требует статусной модели | Обоснование                                                                                                                         |
|-----------------------|--------------------------|-------------------------------------------------------------------------------------------------------------------------------------|
| **Персоны**           | Да                       | Пользователь может быть активным, заблокированным или удалённым. От статуса зависит возможность входа в систему и выполнения действий. |
| **Клиенты**           | Да                       | Клиент может быть активным, заблокированным. Статус определяет возможность бронирования слотов и получения уведомлений.               |
| **Сотрудники**        | Да                       | Сотрудник может быть действующим, уволенным, заблокированным. Статус определяет возможность назначения слотов и отображения в списке мастеров. |
| **Слоты обслуживания**| Да                       | Слот проходит путь от создания (свободен) через бронирование до выполнения или отмены. Статус определяет доступность слота для бронирования. |

## Exercise 01 — Жизненный цикл объекта «Слоты обслуживания»

### Статусная модель

| № | Статус                  | Исходное состояние     | Инициатор / событие                | Выполняемые действия                                                        | Условия / проверки                                               | Следующий статус                            |
|---|-------------------------|------------------------|------------------------------------|-----------------------------------------------------------------------------|------------------------------------------------------------------|---------------------------------------------|
| 1 | **Свободен**            | — (начало ЖЦ)          | Менеджер / UC02                    | Менеджер создаёт слот: указывает дату, время, мастера                       | Проверка: данный слот у данного мастера не создан ранее          | Забронирован; Удалён (менеджером)           |
| 2 | **Забронирован**        | Свободен               | Клиент / UC03; Менеджер / UC03     | Клиент или менеджер выбирает слот, указывает услугу, подтверждает бронь     | Проверка: слот всё ещё свободен; клиент существует в системе     | Выполнен; Отменён клиентом; Отменён барбершопом |
| 3 | **Выполнен**            | Забронирован           | Менеджер / ручное действие         | Менеджер проставляет отметку о выполнении услуги                            | Проверка: дата и время слота уже наступили                       | — (конец ЖЦ)                               |
| 4 | **Отменён клиентом**    | Забронирован           | Клиент / инициатива клиента        | Клиент отменяет бронирование; система освобождает слот                      | Проверка: до начала слота ещё есть время (бизнес-правило)        | Свободен (слот возвращается в пул)          |
| 5 | **Отменён барбершопом** | Свободен; Забронирован | Менеджер / инициатива барбершопа   | Менеджер отменяет слот (напр. мастер заболел/уволился); система уведомляет клиента | Если слот был забронирован — отправить СМС клиенту об отмене | — (конец ЖЦ)                               |

### Диаграмма состояний (текстовая)

```
                    [Создание слота]
                    Менеджер, UC02
                          │
                          ▼
                    ┌───────────┐◄────────────────────────────────────────────────────┐
                    │ Свободен  │                                                     │
                    └─────┬─────┘                                                     │
                          │                      │                                    │
          Клиент/Менеджер │ UC03         Менеджер│ удаляет свободный слот             │
          выбирает слот   │                      │                                    │
                          ▼                      ▼                                    │
                   ┌─────────────┐         [Слот удалён]                              │
                   │ Забронирован│          (конец ЖЦ)                                │
                   └──────┬──────┘                                                    │
                          │                                                           │
              ┌───────────┼──────────────────────────────────┐                        │
              │           │                                  │                        │
   Менеджер   │    Клиент │ отменяет бронь  Менеджер/система │ отменяет               │
   отмечает   │    (до наступления слота)   (мастер уволился)│                        │
   выполнение │           ▼                                  ▼                        │
              │    ┌──────────────────┐  ┌────────────────────────┐                   │
              ▼    │ Отменён клиентом │  │  Отменён барбершопом   │                   │
         ┌─────────┤                  │  │  (СМС клиенту)         │                   │
         │Выполнен │                  │  └────────────────────────┘                   │
         └─────────┘                  │           (конец ЖЦ)                          │
          (конец ЖЦ)                  │                                               │
                                      └───────────────────────────────────────────────┘
                                       Слот возвращается в пул свободных
```

> **Пояснение:** «Отменён клиентом» — **не конечный** статус ЖЦ. Слот после отмены клиентом возвращается в статус «Свободен» и снова становится доступным для бронирования. Единственные конечные статусы ЖЦ: **Выполнен** и **Отменён барбершопом** (и Удалён менеджером).

### Доработка UC в части смены статуса

**UC03 — дополнение:** После подтверждения бронирования клиентом (шаг 9) статус слота меняется с **«Свободен»** на **«Забронирован»**. При отказе клиента от услуги слот переходит в статус **«Отменён клиентом»**, после чего система автоматически переводит его обратно в **«Свободен»** (слот возвращается в пул свободных).

**UC02 — дополнение:** При создании слота менеджером статус устанавливается **«Свободен»**. При отмене слота менеджером (альтернативный сценарий, перенос мастера) статус меняется на **«Отменён барбершопом»**, система отправляет СМС клиенту.

**Новый UC — Отмена услуги по инициативе клиента:**
1. Клиент открывает список своих бронирований.
2. Клиент выбирает бронирование и нажимает «Отменить».
3. Система проверяет, что до начала слота осталось более N часов (бизнес-правило).
4. Система изменяет статус слота с «Забронирован» на «Свободен».
5. Система направляет клиенту подтверждение отмены по каналу связи.

### Сущность «Сотрудники»

| № | Статус           | Исходный статус | Инициатор / событие              | Действия                                                              | Условия / проверки                                          | Следующий статус          |
|---|------------------|-----------------|----------------------------------|-----------------------------------------------------------------------|-------------------------------------------------------------|---------------------------|
| 1 | **Активен**      | — (начало ЖЦ)   | Менеджер / Администратор         | Сотрудник добавлен в систему, может быть назначен в расписание        | —                                                           | Уволен; Заблокирован      |
| 2 | **Заблокирован** | Активен         | Администратор                    | Учётная запись временно заблокирована (дисциплинарная мера); вход в систему запрещён | —                                              | Активен (разблокирован); Уволен |
| 3 | **Уволен**       | Активен; Заблокирован | Менеджер / Администратор   | Сотрудник помечается уволенным; доступ в систему закрывается автоматически; его будущие слоты требуют обработки | Проверка: есть ли будущие слоты с клиентами — уведомить их  | Удалён (конечный рабочий статус) |
| 4 | **Удалён**       | Уволен          | Администратор                    | Soft delete; данные сохранены для истории (слоты, история оплат)      | Нет будущих забронированных слотов; прошло более 1 года с момента увольнения | — (конец ЖЦ) |

> **Пояснение:** «Заблокирован» — временная мера, применяется только к активным сотрудникам. Уволенный сотрудник не переходит в «Заблокирован» (блокировка доступа происходит автоматически при увольнении). Конечный статус рабочего цикла — «Уволен»; физическое удаление — административная процедура после установленного срока хранения данных.

#### UC02 — Сформировать расписание мастера

**Роль:** Менеджер  
**Предусловие:** Менеджер аутентифицирован. В системе есть активные сотрудники с ролью «Мастер».  
**Результат:** Слот создан в расписании мастера со статусом «Свободен».

| № шага | Действие пользователя / системы |
|--------|----------------------------------|
| 1 | Менеджер открывает раздел «Расписание» |
| 2 | Менеджер нажимает «Добавить слот» |
| 3 | Менеджер выбирает дату из календаря (не ранее текущей) |
| 4 | Менеджер выбирает временной интервал (1 час) из доступных |
| 5 | Менеджер выбирает мастера из списка активных сотрудников с ролью «Мастер» |
| 🟢 5а (новый) | **Система проверяет:** у выбранного мастера нет слота на указанные дату и время. Если слот уже существует — отображается сообщение об ошибке, действие прерывается. |
| 6 | Менеджер нажимает «Подтвердить» |
| 🟢 6а (новый) | **Система сохраняет слот** и **устанавливает статус = «Свободен»**. |
| 🟢 6б (новый) | **Система записывает в журнал:** ID слота, ID мастера, ID менеджера, дата и время создания. |
| 7 | Слот отображается в расписании со статусом «Свободен» и доступен для бронирования клиентами |

**Альтернативный сценарий — удаление свободного слота:**

| № шага | Действие пользователя / системы |
|--------|----------------------------------|
| А1 | Менеджер выбирает существующий слот со статусом «Свободен» |
| А2 | Менеджер нажимает «Удалить» |
| А3 | Система запрашивает подтверждение |
| А4 | Менеджер подтверждает |
| 🟢 А5 (новый) | **Система удаляет слот** и **записывает в журнал:** ID слота, кто удалил, дата и время удаления. |

**Альтернативный сценарий — изменение забронированного слота (перенос мастера):**

| № шага | Действие пользователя / системы |
|--------|----------------------------------|
| Б1 | Менеджер выбирает слот со статусом «Забронирован» |
| Б2 | Менеджер вносит изменение (дата/время/мастер) или отменяет слот |
| Б3 | Система запрашивает подтверждение; предупреждает, что клиент записан |
| Б4 | Менеджер подтверждает |
| 🟢 Б5 (новый) | **Система изменяет статус слота на «Отменён барбершопом»** и **направляет клиенту уведомление об отмене** через выбранный канал связи (SMS/TG/WA/VK). |

#### UC03 — Записаться на услугу (бронирование слота)

**Роль:** Клиент (зарегистрированный / незарегистрированный)  
**Предусловие:** В системе есть свободные слоты мастеров.  
**Результат:** Слот забронирован; клиент получил подтверждение.

| № шага | Действие пользователя / системы |
|--------|----------------------------------|
| 1 | Клиент открывает страницу бронирования |
| 2 | Клиент выбирает услугу из списка |
| 3 | Система отображает мастеров, оказывающих выбранную услугу (по «Услуги мастера») |
| 4 | Клиент выбирает мастера |
| 5 | Система отображает свободные слоты выбранного мастера |
| 6 | Клиент выбирает слот |
| 7 | Клиент нажимает «Забронировать» |
| 8 | Система проверяет, что слот всё ещё свободен (статус = «Свободен») |
| 9 | Клиент подтверждает бронирование |
| 🟢 10 (уточнён) | **Система изменяет статус слота с «Свободен» на «Забронирован»** и записывает в слот: client_id, service_id. |
| 🟢 11 (уточнён) | **Система формирует и отправляет клиенту извещение** о подтверждении бронирования через выбранный канал связи (SMS/TG/WA/VK). Запись о факте отправки сохраняется в «Извещение клиента». |
| 🟢 11а (новый) | **Система записывает в журнал:** ID слота, ID клиента, ID услуги, ID менеджера (если бронировал менеджер), дата и время бронирования. |
| 12 | Система отображает страницу подтверждения с деталями бронирования |

**Альтернативный сценарий — отмена бронирования клиентом:**

| № шага | Действие пользователя / системы |
|--------|----------------------------------|
| О1 | Клиент открывает раздел «Мои бронирования» |
| О2 | Клиент выбирает бронирование и нажимает «Отменить» |
| О3 | Система проверяет бизнес-правило: до начала слота осталось более N часов |
| 🟢 О4 (новый) | **Система изменяет статус слота с «Забронирован» на «Отменён клиентом»**, после чего **автоматически переводит слот в статус «Свободен»** (слот возвращается в пул доступных). |
| 🟢 О5 (новый) | **Система направляет клиенту подтверждение отмены** через выбранный канал связи. **Запись о факте отправки** сохраняется в «Извещение клиента». |
| 🟢 О6 (новый) | **Система записывает в журнал:** ID слота, ID клиента, дата и время отмены, причина (инициатива клиента). |
