# Проект 11: Проектирование пользовательского взаимодействия (UI/UX)

## Введение

Разработка визуальных форм — зона ответственности UI-дизайнера. Содержание экранных форм и движение между ними — зона ответственности аналитика. Рассматривается проектирование пользовательского интерфейса с точки зрения аналитика.

## Литература

1. Карл Вигерс, Джой Битти, «Разработка требований к программному обеспечению», издание третье.
2. Алан Купер, Роберт Рейман, Девид Кронин «Об интерфейсе. Основы проектирования взаимодействия».
3. [Как создать полезный wireframe](https://www.internet-technologies.ru/articles/kak-sozdat-poleznyy-wireframe.html)

## Теоретические сведения

**UX (User Experience)** — опыт/впечатление пользователя от работы с интерфейсом. **UI (User Interface)** — внешний вид, цветовая гамма, читабельность. **Ключевой сценарий** — взаимодействие пользователя в определенной роли с системой в рамках целевых задач. **Экранные формы** (wireframe) делятся на фреймы: список экземпляров, карточка атрибутов, связанные сущности. **Вспомогательные операции:** поиск, фильтрация, сортировка.

## Описание задач

### Задача 1. Запись на стрижку (Sign up for a haircut)

Руководство сети барбершопов приняло решение о внедрении системы, обеспечивающей онлайн-запись на прием. Основная цель — развитие бизнеса путем расширения клиентской базы за счет возможности онлайн-записи, а также снижение трудозатрат сотрудников и уменьшение ручного труда за счет автоматического информирования клиентов по каналам связи.

Запись может осуществлять как зарегистрированный, так и незарегистрированный посетитель сайта. При записи можно выбрать услугу, мастера и время из свободных интервалов. Система должна обеспечивать автоматическую отправку напоминаний клиентам через выбранный клиентом канал связи (Telegram, WhatsApp, VK, СМС) по настроенному менеджером расписанию. После получения услуги система предлагает клиенту оценить услугу и написать предложения по улучшению работы.

Расписание мастеров и выполняемые каждым мастером услуги должен вводить менеджер, возможно, это будет не один человек. Он же отвечает за актуальность расписания и при необходимости корректирует его, осуществляет связь с клиентами в ручном режиме, проставляет отметку о выполнении услуги, начисляет и принимает оплату, передает данные об оплате в бухгалтерию. Также менеджер может получать отчеты о выполненных услугах и просматривать отзывы клиентов.

Любой мастер имеет возможность посмотреть расписание и запись на свои услуги, отзывы клиентов.

## Задания

### Exercise 00 — Выбор формы представления продукта

**Для задачи 1** укажите: устройства, тип ПО, способы управления, локализацию. Табличный вид.

### Exercise 01 — Экранные формы классификаторов и справочников

**Для задачи 1**:
1. Составьте список классификаторов и справочников.
2. Разработайте макеты: название, фрейм списка, фрейм операций, вызовы.
3. Опишите основные операции (права, условия, результат) и обеспечивающие (сортировка, фильтр, поиск, дублирование, расчеты).
4. Укажите логирование. Результаты в таблицах.

### Exercise 02 — Данные на экранных формах классификаторов и справочников

**Для задачи 1** опишите поля на форме списка (наименование, описание, формат), потребности пагинации, проверки и сообщения об ошибках. Табличный вид.

### Exercise 03 — Ключевые сценарии ролей

**Для задачи 1** разработайте ключевые сценарии для ролей (менеджер, мастер, клиент):
1. Схемы задач (прямоугольники, стрелки).
2. Для каждого экрана укажите предназначение, начало и окончание.

### Exercise 04 — Список экранных форм

**Для задачи 1** составьте список экранных форм: идентификатор, назначение, другие действия, данные, права доступа. Табличный вид.

### Exercise 05 — Экранные формы (wireframe)

**Для каждой формы** из Exercise 04 разработайте макет:
1. Название, фреймы, вызовы, роли.
2. Основные операции (права, условия, результат).
3. Обеспечивающие операции.
4. Данные (список и карточка: пагинация, поля, формат).
5. Логирование.

### Exercise 06 — Описание контролей

**Для задачи 1** опишите контроли ввода на экранных формах:
1. Идентификатор экрана, роль, назначение, объект.
2. Пагинация, наименование поля, мнемоника, описание контроля, сообщение об ошибке, результат.
3. Логирование при негативном завершении. Табличный вид.
