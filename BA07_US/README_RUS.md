# Проект 07. Проектирование функциональных требований

## Введение

## Теоретические сведения

### 1. Операции над объектом (экземпляром объекта)

При рассмотрении операций над объектом следует рассмотреть:
- создание (CREATE);
- редактирование (UPDATE);
- чтение (READ);
- удаление (DELETE);
- подтверждение выполнения, откат;
- форму визуализации;
- участие в интеграции;
- сохранение истории изменений;
- перевод в архив;
- другие операции (расчеты, проверки).

### 2. Особенности операций

Следует осторожно относиться к операции удаления/редактирования записи. В некоторых случаях удаление записи в одном объекте может привести к некорректности в других объектах. Для справочников применяют признак «Архив» или даты начала и окончания актуальности.

### 3. Роли, ролевая модель, права доступа

Проверяется и актуализируются роли, указываются действия ролей над объектами системы. Описываются права доступа ролей к объектам в соответствии с функциями.

### 4. Жизненный цикл сущности

Объекты системы могут проходить сложный жизненный путь. Формат описания статусной модели: диаграмма переходов состояний или таблица.

### 5. Проверки

Описание проверок должно содержать:
1. операцию и привязку к ней;
2. проверяемый атрибут;
3. описание проверки;
4. критичность;
5. сообщение об ошибке;
6. действие при ошибке.

**Для задачи 1** разработайте статусную модель объекта «Слоты обслуживания». Определите состояния, названия статусов, предусмотрите состояние отказа и непредоставления услуги. Разработайте диаграмму состояний.

**Для задачи 1** разработайте статусные модели объектов, определенных в Ex.00 (кроме «Слоты обслуживания»). Представьте в табличном виде.

**Для задачи 1** опишите функциональность справочников: Клиенты, Сотрудники, Роли сотрудника, Услуги, Услуги мастера.

### Exercise 05 — Детализация действий над объектом «Слоты обслуживания»
