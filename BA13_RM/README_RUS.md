## Теоретические сведения

### 1. Общие понятия

Разработка интеграции содержит шаги:
1. Выявление потребности в интеграции.
2. Определение атрибутов качества интеграции.
3. Выбор систем взаимодействия.
4. Определение требований к преобразованию (маппинг).
5. Выбор решения интеграции (стили и сценарии).
6. Определение требований к журналированию.
7. Описание ошибок.
8. Разработка вызовов интеграции.
9. Интеграционное тестирование.

Системный аналитик участвует в этапах 1-7.

### 2. Потребность в интеграции

Потребность выясняется во время анализа бизнес-требований, требований заинтересованных сторон, функциональных требований.

### 3. Критерии интеграции

1. Объемы и количество данных
2. Сроки и частота передачи
3. Форматы и схема данных, бизнес-логика
4. Своевременность передачи (синхронность/асинхронность)
5. Маппинг

### 4. Стили интеграции

1. **Общая база данных** — единое хранилище.
2. **Обмен файлами** (CSV, XML, JSON, YAML).
3. **Обмен сообщениями** — быстрая, асинхронная передача.
4. **Удаленный вызов процедур** (SOAP, REST).
