# Проект 06: База данных и словарь данных

## Введение

Построение логической модели базы данных: описание классов (объектов), их атрибутов, диаграмма классов UML.

## Теоретические сведения

**Диаграмма классов** — структурная диаграмма UML, демонстрирующая классы системы, их атрибуты, методы и взаимосвязи. Состоит из трех разделов: имя класса (жирный, с заглавной буквы), атрибуты (с маленькой буквы), методы (с маленькой буквы).

**Жизненный цикл сущности** — ряд состояний (статусов), которые проходит экземпляр объекта. Для отслеживания в сущность добавляется атрибут «Статус».

**Справочники** — сущности, содержащие данные для заполнения в других сущностях. Разрабатываются перед основными объектами.

**Атрибуты объекта** — поля, содержащие свойства объекта. Описание атрибута включает: мнемонику, наименование, тип, обязательность, значение по умолчанию, длину, комментарии.

## Описание задач

### Задача 1. Запись на стрижку (Sign up for a haircut)

Руководство сети барбершопов приняло решение о внедрении системы, обеспечивающей онлайн-запись на прием. Основная цель — развитие бизнеса путем расширения клиентской базы за счет возможности онлайн-записи, а также снижение трудозатрат сотрудников и уменьшение ручного труда за счет автоматического информирования клиентов по каналам связи.

Запись может осуществлять как зарегистрированный, так и незарегистрированный посетитель сайта. При записи можно выбрать тип услуги: парикмахерские или косметологические, а также саму услугу, мастера и время из свободных интервалов. Система должна обеспечивать автоматическую отправку напоминаний клиентам через выбранный клиентом канал связи (Telegram, WhatsApp, VK, СМС) по настроенному менеджером расписанию. После получения услуги система предлагает клиенту оценить услугу и написать предложения по улучшению работы.

Расписание мастеров и выполняемые каждым мастером услуги должен вводить менеджер, возможно, это будет не один человек. Он же отвечает за актуальность расписания и при необходимости корректирует его, осуществляет связь с клиентами в ручном режиме, проставляет отметку о выполнении услуги, начисляет и принимает оплату, передает данные об оплате в бухгалтерию. Также менеджер может получать отчеты о выполненных услугах и просматривать отзывы клиентов.

Любой мастер имеет возможность посмотреть расписание и запись на свои услуги, отзывы клиентов.

**Сокращения:** Слот — период времени длительностью 1 час, указано начальное время.

**UC01. Зарегистрироваться клиенту (саморегистрация)** — клиент регистрируется, чтобы записаться на обслуживание. Основной сценарий: клиент открывает страницу регистрации, вводит номер телефона и имя, система подтверждает, что телефон не зарегистрирован, клиент вводит пароль, система регистрирует и отправляет СМС.

**UC02. Сформировать расписание мастера** — менеджер создает расписание в виде слотов. Основной сценарий: менеджер открывает страницу ввода слотов, выбирает дату, слот и мастера, система подтверждает что слот не забронирован, менеджер подтверждает, система закрепляет слот.

**UC03. Забронировать слот на обслуживание** — клиент бронирует визит. Основной сценарий: клиент открывает страницу выбора слотов, система формирует список свободных слотов, клиент выбирает слот, систему формирует список услуг, клиент выбирает услугу и мастера, система подтверждает что слот свободен, клиент подтверждает бронирование, система закрепляет слот и отправляет СМС.

**UC04. Зарегистрировать клиента (менеджер)** — менеджер регистрирует клиента по телефону. Основной сценарий: менеджер открывает страницу регистрации, вводит номер телефона и имя, система подтверждает что телефон не зарегистрирован, регистрирует клиента, генерирует пароль и отправляет СМС.

## Задания

### Exercise 00 — Описание класса «Персоны»

**Для задачи 1** опишите класс «Персоны»:
1. Укажите назначение класса.
2. Определите атрибуты: идентификатор персоны, регистрационные данные (логин, пароль), имя (отчество), номер телефона, дата регистрации.
3. Для атрибутов укажите: наименование, ключ (первичный, внешний), тип данных, ограничение длины, обязательность, значение по умолчанию, комментарии.

### Exercise 01 — Описание сущностей «Клиенты» и «Сотрудники»

**Для задачи 1** опишите сущности «Клиенты», «Сотрудники»:
1. Укажите назначение сущностей.
2. Определите атрибуты: идентификатор записи, идентификатор сущности «Персоны» (внешний ключ), дата регистрации.
3. Для атрибутов укажите параметры (см. Exercise 00).

### Exercise 02 — Описание сущностей справочников

**Для задачи 1** опишите сущности справочников: «Роли сотрудника», «Услуги», «Услуги мастера»:
1. Укажите назначение каждой сущности.
2. Определите атрибуты.
3. Для атрибутов укажите параметры.

### Exercise 03 — Описание сущности «Слоты обслуживания»

**Для задачи 1** опишите сущность «Слоты обслуживания»:
1. Укажите назначение.
2. Определите атрибуты: идентификатор записи, дата, время начала слота, мастер (внешний ключ к «Сотрудники»), клиент (внешний ключ к «Клиенты»).
3. Для атрибутов укажите параметры.

### Exercise 04 — Создание диаграммы классов

**Для задачи 1** постройте диаграмму классов в нотации UML:
1. Разместите в диаграмме классы из Exercises 00-03.
2. Укажите классы в нотации UML (название — жирный с заглавной, атрибуты — с маленькой буквы).
3. Укажите первичные и внешние ключи.
4. Установите связи между классами, опишите смысловыми словами.
5. На связях укажите мощность: 1:1, 1:*, *:1.

### Exercise 05 — Описание сущностей «Скидки клиенту» и «Извещение клиента»

**Для задачи 1** опишите сущности «Скидки клиенту», «Извещение клиента»:
1. Укажите назначение.
2. Выделите атрибуты.
3. Определите параметры атрибутов.
